# Claude Code 指示書：99走行再実験後の図化（元図化プログラム再利用）

作成日: 2026-09-17
目的: 新しい理論的に正しい相互作用で 99 走行を再実行した後、**元の実験で使った図化プログラムを、パス変更以外は変えずに再利用して図化する**。

---

## 0. 基本方針

今回の図化では、**図化ロジックを変更してはいけない**。

変更してよいのは原則として次だけ:

1. 入力ファイルのパス
2. 出力ファイルのパス
3. 実行対象フォルダ名

それ以外は変更禁止。

特に以下は禁止:

- 軸範囲の変更
- 目盛りやラベルの変更
- 色やマーカーの変更
- 凡例の変更
- 平滑化の追加
- 補間の追加
- 間引きの追加
- 閾値処理の追加
- 丸めの追加
- 近似計算の追加
- 旧 CSV / 旧中間ファイルが無いからといって、図化コード側のロジックを変更して辻褄合わせすること

**方針は常に「図化コードをデータに合わせる」のではなく、「出力データ形式を旧図化コードに合わせる」こと。**

---

## 1. 対象図

最低限、以下の3種類を元実験と同じ図化プログラムで再生成すること。

### (A) 初期の複素図
- t=0 の複素状態 `z` を複素平面にプロットした図
- 旧図化プログラムをそのまま使う
- 新しい実験結果に対しては、入力パスだけ変更して実行する

### (B) 終了時の複素図
- 最終 step の複素状態 `z` を複素平面にプロットした図
- 旧図化プログラムをそのまま使う
- 新しい実験結果に対しては、入力パスだけ変更して実行する

### (C) インフレーション図
- 元実験で描いていたインフレーション図（縦軸・横軸・スケール・計算法・スタイルを含めて同一）
- 旧図化プログラムをそのまま使う
- 必要な入力ファイル形式・列名・中間ファイル名があれば、新しい走行結果から**同じ形式で再生成する**こと
- 図化プログラム本体の計算ロジックは変えない

---

## 2. 入出力互換性の原則

元の図化プログラムが読んでいる入力形式を先に確認すること。

- `states.npz` を直接読むのか
- `sample_metrics.csv` を読むのか
- 別の中間 CSV / JSON / NPZ を読むのか
- ファイル名を固定で期待しているのか

これを確認したうえで、**新しい再実験の出力を旧図化プログラムがそのまま読める形へ揃えること。**

つまり:

- 列名を合わせる
- 配列名を合わせる
- ディレクトリ構造を合わせる
- ファイル名を合わせる

図化プログラム側の変更で吸収してはいけない。

---

## 3. 図化プログラム再利用の厳格ルール

### 3.1 コピーの扱い
- 元の図化プログラムは、正本として別保存すること
- 実行用には**物理コピー**を作ってよい
- ただしコピー後も、変更は**パス文字列の差し替えだけ**とする

### 3.2 diff の確認
- 実行前に、元図化プログラムと実行用コピーの diff を取ること
- パス文字列以外に差分があれば停止し、報告すること

### 3.3 同一性の判定
- 「ロジックは同じ」は不可
- 「見た目が同じ」は不可
- **文字単位 diff で、パス変更以外の差分がないこと**を確認すること

---

## 4. もし図が生成できない場合の対処順序

図がそのまま生成できない場合、次の順序で対処すること。

1. 図化プログラムの入力パスが正しいか確認
2. 新実験の出力ファイル名が旧実験と一致しているか確認
3. データ形式（CSV列名、NPZキー名、JSONキー名など）が一致しているか確認
4. 必要なら、**図化プログラムを変えずに**、新しい結果から旧形式の中間ファイルを生成する
5. それでもだめなら停止して報告

**図化プログラム本体のロジック変更は最終手段ではなく、禁止。**

---

## 5. 生成すべき成果物

各 run / 各代表ケースについて、少なくとも以下を保存すること。

1. 初期複素図 PNG
2. 終了時複素図 PNG
3. インフレーション図 PNG
4. 使用した図化プログラムのコピー
5. 元図化プログラムとの diff（パス変更以外差分なしの証跡）
6. 図化に用いた入力ファイル一覧
7. 図化ログ

必要なら SVG も併せて保存すること。

---

## 6. 出力先フォルダ構成の推奨

新しい再実験フォルダの下に、たとえば次のような構成を作ること。

- `plot_scripts_original/` : 元図化プログラムの正本コピー
- `plot_scripts_run/` : 実行用コピー（パス変更のみ）
- `plots/initial_complex/`
- `plots/final_complex/`
- `plots/inflation/`
- `plot_logs/`
- `plot_diffs/`

---

## 7. 最終確認事項

図化完了後、必ず次を確認すること。

1. 元図化プログラムと実行用図化プログラムの差分はパス変更のみか
2. 3種類の図がすべて生成されたか
3. 出力図のファイル名と保存場所が整理されているか
4. どの入力ファイルからどの図を作ったか追跡可能か
5. 今後の論文やノートに再利用可能な形で保存されているか

---

## 8. Claude Code への明示命令

Claude Code は以下を守ること。

- 元の図化プログラムを勝手に簡略化しない
- 新しい matplotlib / plotly / 別スクリプトへ書き換えない
- 旧ロジックを推測で再実装しない
- パス変更以外の変更を加えない
- もし旧図化コードがそのまま動かないなら、図化コードではなく入力データ整形側で吸収する
- 勝手に見た目を改善しない
- 旧図と比較しやすいことを最優先する

---

## 9. 要約

今回の図化方針は一言でいえば次である。

> **初期複素図・終了時複素図・インフレーション図は、元の図化プログラムをパス変更以外無変更で再利用して描く。**

もしそのまま動かない場合は、**図化コードを変えるのではなく、新しい走行結果を旧図化コードが読める形式に揃える。**
