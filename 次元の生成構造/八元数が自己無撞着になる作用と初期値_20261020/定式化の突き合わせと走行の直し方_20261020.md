## 1. 定式化は一致した

§1〜§7 が同じ結論で、数値も一致する。

| 事項 | 値 |
|---|---|
| 作用の形 ȯ_e = u_e o_e、u_e ∈ Im(𝕆)、ノルム厳密保存 | 誤差 5.3×10⁻¹⁵ |
| 双線形は 3 本、Im(x ȳ) = Re(y)Im(x) − Re(x)Im(y) − Im(x)×Im(y) | 誤差 2.2×10⁻¹⁵ |

| 定理 B：E₈ の根で消える / NULL28 で消えない | 5.8×10⁻¹⁶ / 6.000 |
| 自己無撞着：∃D ∈ g₂ で u_e o_e = D o_e（8N 本 vs 14） | ― |

### 採用すべき方の書き方

**振動数の拘束は Claude Code の書き方を採る。** chat 側は「ω₁ + ω₂ + ω₃ = 0（符号付き）、最小比 1 : 1 : −2」と書いたが、固有値からは絶対値しか出ないので検定しにくい。Claude Code の

> **ω₁ + ω₂ = ω₃、最小の比は 1 : 1 : 2**

の方が、そのまま数値で検定できて良い。chat 側の `作用の定式化と探索空間_20261020.md` §5 はこちらに直す。

### 定理 B に足すべき第三の消え方（Claude Code の発見）

chat 側の定式化は関係 w_ef（二要素）までで止めていたので、**三要素が同時に入る ASSOC 型が範囲外だった**。Claude Code の

u_e o_e = κ|x_e| Σ_{f,g} ⟨w_e w_f, w_g⟩ [w_e, w_f, w_g]

は、結合子を使う本質的に八元数的な作用で、chat 側の分類に入っていない。そして

> **相手を二次モーメント S = Σ w wᵀ を通してしか見ない作用は、S ∝ I（2-デザイン）なら消える**

という消え方を持つ（E₈ 240・正軸体 16 で確認済み）。これは定理 B の (a)(b) と独立な **(c)** で、より一般的でもある。**定理 B に (c) として足す。**

## 2. 走行について確かめたこと

`results/run_stderr.txt` に divide by zero / overflow / invalid value が出ていたので、原因を調べた。numpy の警告は既定で「場所ごとに一度」しか出ないので、継続的な発散とは限らない。

### 再現しなかったもの

- **N5 の自明解への落下：** `least_squares` に渡す残差 [Σo, Σo²] は o = 0 を厳密解に持つので自明解に落ちる危険があるが、SEED = 20261020 では最小ノルム 0.309、全体 2.12 で健全だった。ただし別の初期点では最小ノルム 0.13 まで下がった例がある（seed 103）。**潜在的な危険は実在する。** Σ|o_e|² = N のような大きさの拘束を足すのが安全。
- **PAIR_L の発散：** RAND8・RAND16、κ = ±1 のいずれも 6000 歩を完走し、最小ノルムは縮まなかった（1.5〜2.0 を維持）。Lohe 型なので同期・反同期はするが破綻しない。
- **ASSOC の発散：** N5・RAND8 で 6000 歩を完走。N4・NULL28・ORTHO_AB は初期 \|F\| = 0 で静止（積分しない）。

### 実在する問題（確認できたもの）

**(1) RK4 はノルムを保たない。** 連続の方程式は \|o_e\| を厳密に保つが、RK4 の中間段 X + dt/2·k は保たない。測った値：

| 走行 | ノルムのずれ（6000 歩） |
|---|---|
| RAND16 + PAIR_L、RK4 | 2.1×10⁻⁵ |
| N5 + ASSOC、RK4 | **2.7×10⁻⁴** |

W = X/\|X\| を毎回取り直す実装なので、このずれは作用そのものを汚す。

**(2) 計算量が非常に大きい。** F_assoc は O(N³)（8³ の構造定数込み）。測った値：

| N | F_assoc 一回 | 6000 歩 × RK4 4 段 |
|---|---|---|
| 16 | 12.5 ms | **5.0 分/試行** |
| 32 | 89.2 ms | **35.7 分/試行** |
| 240（E₈） | 約 17 秒（外挿） | ― |

`run_log.txt` が 0 バイトなのは、最初の print が E₈ の ASSOC 検査（17 秒）より後にあることと、RAND16 × ASSOC × κ 二通りで 10 分かかることで説明がつく。**止まっているのではなく、遅いだけの可能性が高い。**

## 3. 直し方（どちらも検証済み）

### (1) PAIR 型（F = u o、u 純虚）には指数写像を使う

u_e と o_e はアルティンの定理で結合的な部分代数を張るので、

**o_e ← exp(u_e dt) o_e、 exp(u dt) = cos(\|u\|dt) + (u/\|u\|) sin(\|u\|dt)**

が厳密に定義でき、**ノルムが機械精度で保たれる**。RK4 より速い。

| 方法 | ノルムのずれ（RAND16、6000 歩） | 時間 |
|---|---|---|
| RK4 | 2.1×10⁻⁵ | 11.5 秒 |
| **指数写像** | **4.9×10⁻¹⁵** | **3.2 秒** |

```python
def exp_step(X, U, dt):
    """o_e <- exp(u_e dt) o_e。U は純虚の (N,8)。"""
    w = np.linalg.norm(U, axis=1, keepdims=True)
    g = np.where(w < 1e-300, np.tile(E[0], (len(X), 1)),
                 np.cos(w*dt)*E[0][None, :]
                 + np.sin(w*dt)*np.divide(U, np.where(w < 1e-300, 1, w)))
    return mul(g, X)
```

PAIR_L なら u_e = Σ_{f≠e} Im(w_f w̄_e)（現在の実装の `prods.sum(0)`）をそのまま渡せばよい。

### (2) ASSOC 型（F ⊥ o）には射影（retraction）を入れる

ASSOC は ⟨[x,f,g], x⟩ = 0 で速度が位置に直交する型なので指数写像は使えないが、厳密解が \|o_e\| を保つ以上、各歩のあとに半径を戻すのは正当な retraction である。

```python
def retract(X, r0):
    return X * (r0 / np.linalg.norm(X, axis=1))[:, None]
```

| 方法 | ノルムのずれ（N5 + ASSOC、6000 歩） |
|---|---|
| RK4 のみ | 2.7×10⁻⁴ |
| **RK4 + 射影** | **2.2×10⁻¹⁶** |

### (3) 配置生成に大きさの拘束を足す

`least_squares` の残差に Σ\|o_e\|² − N を足す（o = 0 を解から外す）。

### (4) F_assoc の計算量

`left - right` を e ごとに (N,N,8) で確保しているので O(N³) のメモリ往復が重い。重み `wgt` が f, g について反対称なので、f < g の三角部分だけ回せば 2 倍、結合子の einsum を一度にまとめればさらに速くなる。E₈ 240 を毎回の積分で使うのは現実的でないので、**E₈ は検査（一回）だけに限り、積分は N ≤ 32 に絞る**のが実際的。
